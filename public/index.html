About

I’m a frontend and full-stack engineer. Most of my work now happens alongside AI agents.

So I build the tools I want for that: ways to see what an agent actually did, and to stay the one who decides what ships. Everything here is open source.

Path

  1. 01Frontend: interfaces people actually use.
  2. 02Full-stack: UI to APIs, data and deploys on Supabase, Vercel and Cloudflare Workers.
  3. 03AI-native: agents run the ops, I keep the judgment.

Principles

  1. 01Spec before code.
  2. 02No flattery.
  3. 03Verify, then answer.
  4. 04Memory you own: portable, private, correctable.

How I build with agents

  1. →Spec: problem, user stories, out of scope.
  2. →Slice: tickets small enough for one agent session.
  3. →Review the evidence and the diff, then decide.

LEDRING

Status lights for AI agents, and a browser game about stopping one.

How to play

  1. 01Press Start and give CX-417, an AI builder, an idea.
  2. 02Watch it build one web page in real time. It may cut corners.
  3. 03Approve, push back, or stop it. Reach one of 7 endings.
